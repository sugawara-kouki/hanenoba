# 管理者アカウント管理 (CRUD) テスト仕様書

管理者用管理者アカウントCRUD（作成・編集・一覧・削除）処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_ADM_01** | 正常系 | 管理者一覧の表示とソートを実行する | ・全管理者アカウントが表示され、指定カラム（email 等）でソートできること |
| **TS_ADM_02** | 正常系 | 新たな管理者アカウントを追加する | ・DBに管理者レコード（bcrypt暗号化）が新規登録されること<br>・成功後、一覧画面へリダイレクトされること |
| **TS_ADM_03** | 正常系 | パスワードを入力せずにメールアドレスのみを更新する | ・メールアドレスが正常に変更されること<br>・パスワードはもとの値が保持され、エラーにならないこと |
| **TS_ADM_04** | 正常系 | パスワードおよびメールアドレスを更新する | ・メールアドレスとパスワードの両方が正常に更新され、新パスワードでログインできること |
| **TS_ADM_05** | 正常系 | 自分以外の他の管理者アカウントを削除する | ・対象のレコードが `admins` テーブルから物理削除されること |
| **TS_ADM_06** | 異常系 | ログインしている自分自身の管理者アカウントを削除しようとする | ・削除が拒否され、一覧画面へリダイレクトされること<br>・「自分自身は削除できません」という警告Flashが表示されること<br>・レコードが削除されず残っていること |
| **TS_ADM_07** | 異常系 | 重複メールアドレスや確認不一致で保存する（バリデーション失敗） | ・保存が拒否され、ステータス `422 Unprocessable Entity` が返ること<br>・画面上に適切なエラーメッセージが表示されること |
| **TS_ADM_08** | 異常系 | 一般ユーザーのセッションで管理者アカウント管理APIにアクセスする | ・アクセスがブロックされ、管理者ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 自己アカウント削除の防止検証 (TS_ADM_06)

#### 前提条件
*   管理者ユーザーA（ログイン中）が存在すること。
*   別の管理者ユーザーBが存在すること。

#### 操作手順
1.  管理者ユーザーAとしてログインした状態で、管理者一覧画面（`/admin/admins`）へアクセスする。
2.  自分自身（ユーザーA）の行にある「削除」ボタンを押下し、確認ポップアップを承認する（`DELETE /admin/admins/[ユーザーAのID]` を送信）。
3.  削除要求後のリダイレクト先とFlashメッセージを確認する。
4.  データベースのレコード存在状況を確認する。

#### 期待される結果
1.  手順3において、ステータス `302 Found` で `/admin/admins` へリダイレクトされ、画面上部に「自分自身は削除できません」という赤色の警告メッセージが表示されること。
2.  手順4において、`admins` テーブルに管理者ユーザーAのレコードが削除されず、そのまま残っていること。
3.  引き続き管理者ユーザーAとしてのサインインセッションが維持されていること。

---

### シナリオ 2: パスワード空欄でのメールアドレス更新 (TS_ADM_03)

#### 前提条件
*   管理者ユーザーAがログイン状態であること。
*   ユーザーAの登録メールアドレスが `admin@example.com` であり、暗号化パスワードが設定済みであること。

#### 操作手順
1.  ユーザーAの編集画面（`/admin/admins/[ユーザーAのID]/edit`）へアクセスする。
2.  メールアドレス欄を `new_admin@example.com` に変更し、パスワードおよびパスワードの確認欄は**完全に空欄**にしたまま「保存」ボタンを押下する。
3.  送信後の画面遷移とDB値を確認する。

#### 期待される結果
1.  ステータス `302 Found` が返り、一覧画面（`/admin/admins`）へリダイレクトされること。
2.  リダイレクト後、画面上部に「管理者を更新しました」と緑色のFlashが表示されること。
3.  DB上のユーザーAのメールアドレスが `new_admin@example.com` に更新されていること。
4.  DB上のユーザーAの `encrypted_password` カラム値が**変更前のハッシュ値のままであり、更新前のパスワードで引き続きログインができること**。
