# 予約カレンダーマイページ テスト仕様書

予約カレンダーマイページ処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_CAL_01** | 正常系 | ログイン状態でマイページカレンダーにアクセスする | ・ステータス 200 OK となり、カレンダー画面が表示されること<br>・デフォルトで「当月」のカレンダーが表示されること |
| **TS_CAL_02** | 正常系 | 指定月のカレンダーへパラメータを指定してアクセスする | ・指定された月のカレンダーが表示されること<br>・カレンダーの境界日（表示日付範囲の最初と最後）が正しく計算され、その期間の予約イベントがマッピングされること |
| **TS_CAL_03** | 正常系 | 予約セルの状態・配色ロジックの検証 | ・今日の日付、土曜日、日曜日、および月外の日付が正しい配色クラス（`text-pink-500` や `bg-indigo-600` 等）で表示されること<br>・予約イベントがあるセルに、予約ありを指す背景クラス（`bg-indigo-50/40`）が付与されること |
| **TS_CAL_04** | 正常系 | 複数ユーザーのデータ分離（セキュリティ） | ・ログイン中ユーザー以外の予約データは、カレンダー上およびモバイル用リスト上に一切表示されないこと |
| **TS_CAL_05** | 正常系 | 前月・翌月移動リンクの動作 | ・前月・翌月ボタンのリンクパラメータ（`?date=YYYY-MM-DD`）が正しく設定されており、月移動が正常に行えること |
| **TS_CAL_06** | 異常系 | 未ログイン状態でカレンダーへアクセスする | ・アクセスが拒否され、ログイン画面へリダイレクトされること |

## 2. 具体的なテストシナリオ

### シナリオ 1: 他ユーザー予約データの非表示（セキュリティ検証） (TS_CAL_04)

#### 前提条件
*   一般ユーザーA（ログイン状態）、および一般ユーザーB（ログインしていない他ユーザー）が存在すること。
*   イベント1（2026/06/15 開催）が存在し、**ユーザーA**が予約済みであること。
*   イベント2（2026/06/20 開催）が存在し、**ユーザーB**のみが予約済みであること（ユーザーAは未予約）。
*   日付基準パラメータとして `date=2026-06-01` を使用すること。

#### 操作手順
1.  一般ユーザーAとしてログインした状態で、`/mypage/calendar?date=2026-06-01` へアクセスする。

#### 期待される結果
1.  ステータスコード `200 OK` が返却されること。
2.  表示されたカレンダー上の **6月15日のセル** に、イベント1（ユーザーAの予約）のタイトルが含まれていること。
3.  表示されたカレンダー上の **6月20日のセル** に、イベント2（ユーザーBの予約）のタイトルが含まれておらず、予約なし（背景が `bg-white`）のスタイルであること。
4.  スマートフォンサイズ用の予定一覧リストを確認した際、イベント1のみが表示され、イベント2が表示されないこと。

---

### シナリオ 2: 前月・翌月移動 (TS_CAL_05)

#### 前提条件
*   一般ユーザーAが存在し、ログイン状態であること。

#### 操作手順
1.  `/mypage/calendar?date=2026-06-01` へアクセスする。
2.  カレンダーヘッダー部にある「翌月へ進む（＞）」ボタンのリンクURLを確認する。
3.  「翌月へ進む」ボタンをクリックして遷移したページのヘッダー表示を確認する。

#### 期待される結果
1.  初期ページのヘッダーに「2026年6月」と表示されていること。
2.  「翌月へ進む」ボタンのリンク先が `/mypage/calendar?date=2026-07-01`（または翌月の別日付）であること。
3.  ボタンをクリックした結果、ステータス `200 OK` で遷移し、ヘッダーが「2026年7月」に切り替わっていること。
