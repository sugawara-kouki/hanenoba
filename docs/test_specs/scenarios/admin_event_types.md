# イベントタイプ管理 (CRUD) テスト仕様書

管理者用イベントタイプCRUD（作成・編集・一覧・削除）処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_TYP_01** | 正常系 | イベントタイプ一覧で名前や作成日のソートを実行する | ・ソート列および方向（昇順・降順）に従って全レコードが表示されること |
| **TS_TYP_02** | 正常系 | 重複のない新規カテゴリー名を登録する | ・DBに新規イベントタイプレコードが登録されること<br>・登録成功後、一覧画面へリダイレクトされ、成功Flashメッセージが表示されること |
| **TS_TYP_03** | 正常系 | 既存のカテゴリー名を変更する | ・指定したカテゴリーの名前（name）が更新されること<br>・更新成功後、一覧画面へリダイレクトされること |
| **TS_TYP_04** | 正常系 | 紐づくイベントが存在しないイベントタイプを削除する | ・イベントタイプレコードが正常に物理削除されること |
| **TS_TYP_05** | 異常系 | 不正なパラメータで新規保存・更新を行う（空白バリデーション） | ・保存が拒否され、ステータス `422 Unprocessable Entity` が返ること<br>・画面上に「名前を入力してください」とエラーメッセージが表示されること |
| **TS_TYP_06** | 異常系 | すでに存在する同一のカテゴリー名を登録しようとする（重複バリデーション） | ・保存が拒否され、ステータス `422 Unprocessable Entity` が返ること<br>・画面上に「名前はすでに存在します」とエラーメッセージが表示されること |
| **TS_TYP_07** | 異常系 | イベントに割り当て中のイベントタイプを削除しようとする | ・DBの外部キー制約に守られ、削除が拒否されること（`ActiveRecord::InvalidForeignKey` 例外がスローされること） |
| **TS_TYP_08** | 異常系 | 一般ユーザーのセッションでイベントタイプ管理APIにアクセスする | ・アクセスがブロックされ、管理者ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 割り当て中イベントタイプの削除保護検証 (TS_TYP_07)

#### 前提条件
*   管理者ユーザーがログイン状態であること。
*   イベントタイプ「勉強会」（ID: 1）がDBに登録済みであること。
*   イベント1（タイトル「Rails勉強会」）が存在し、そのカテゴリーとして「勉強会（ID: 1）」が設定されていること。

#### 操作手順
1.  イベントタイプ一覧画面（`/admin/event_types`）へアクセスする。
2.  「勉強会（ID: 1）」の行にある「削除」ボタンを押下し、警告ダイアログを承認する。

#### 期待される結果
1.  削除要求（`DELETE /admin/event_types/1`）が発生した際、データベースの外部キー制約違反がトリガーされ、`ActiveRecord::InvalidForeignKey` 例外が発生すること。
2.  「勉強会」のレコードが `event_types` テーブルから**削除されずに残っていること**。
3.  当然、イベント1のレコードもそのまま残っていること。

---

### シナリオ 2: 重複カテゴリー名の防止 (TS_TYP_06)

#### 前提条件
*   管理者ユーザーがログイン状態であること。
*   イベントタイプ「もくもく会」がすでにDBに登録済みであること。

#### 操作手順
1.  新規イベントタイプ作成画面（`/admin/event_types/new`）へアクセスする。
2.  名前に「もくもく会」と入力し、「保存」ボタンを押下する。

#### 期待される結果
1.  サーバーからステータスコード `422 Unprocessable Entity` が返却されること。
2.  画面が再描画され、フォーム内の「名前」入力フィールド付近に「名前はすでに存在します」（または一意性制約エラー）とエラー文言が表示されること。
3.  DBに新たなレコードが追加されておらず、既存の「もくもく会」が1件のみ存在すること。
