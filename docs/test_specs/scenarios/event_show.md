# イベント詳細表示処理 テスト仕様書

イベント詳細表示処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_SHO_01** | 正常系 | ログイン状態で公開中のイベント詳細へアクセスする | ・ステータス 200 OK となり、イベントタイトル、日時、場所、現在の予約状況が正しく表示されること |
| **TS_SHO_02** | 正常系 | 自身が未予約かつ空きのあるイベントにアクセスする | ・「申し込む」ボタンが活性状態で表示され、クリック時に確認メッセージが表示されること |
| **TS_SHO_03** | 正常系 | 自身が予約済みのイベント詳細にアクセスする | ・「申込済」というチェックバッジが表示され、申し込みボタンが表示されないこと |
| **TS_SHO_04** | 正常系 | 定員に達しているイベント詳細にアクセスする | ・「満席」という無効化されたパネルが表示され、申し込みボタンが表示されないこと |
| **TS_SHO_05** | 正常系 | `preview=true` パラメータを付加してアクセスする | ・管理者プレビュー状態となり、申し込みボタンが無効化されて表示されること |
| **TS_SHO_06** | 異常系 | 一般ユーザーが「下書き/非公開」のイベント詳細へアクセスする | ・レコードが存在しないと判定され、404 Not Found エラーが返ること |
| **TS_SHO_07** | 異常系 | 管理者が「下書き/非公開」のイベント詳細へアクセスする | ・ステータス 200 OK となり、詳細画面が表示されること |
| **TS_SHO_08** | 異常系 | 存在しないイベントIDを指定してアクセスする | ・404 Not Found エラーが返ること |
| **TS_SHO_09** | 異常系 | 未ログイン状態でイベント詳細に直接アクセスする | ・アクセスが拒否され、ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 予約ボタンの表示ステータス分岐検証 (TS_SHO_02, TS_SHO_03, TS_SHO_04)

#### 前提条件
*   一般ユーザーAが存在し、ログイン状態であること。
*   以下のイベントデータが登録されていること：
    *   **イベント1**: タイトル「Rails勉強会」、定員5、予約数2（空きあり）※ユーザーAは未予約
    *   **イベント2**: タイトル「Railsもくもく会」、定員2、予約数2（満席）※ユーザーAは未予約
    *   **イベント3**: タイトル「JavaScript勉強会」、定員3、予約数1（空きあり）※ユーザーAが予約済み

#### 操作手順
1.  `/events/[イベント1のID]` へアクセスし、右側のアクション欄を確認する。
2.  `/events/[イベント2のID]` へアクセスし、右側のアクション欄を確認する。
3.  `/events/[イベント3 of ID]` へアクセスし、右側のアクション欄を確認する。

#### 期待される結果
1.  イベント1の画面：「申し込む」というボタンが表示され、フォームの送信先が `/events/[イベント1のID]/bookings` (POST) であること。
2.  イベント2の画面：「満席」というテキストが表示され、申し込みボタンがHTML上に存在しないこと。
3.  イベント3の画面：「申込済」というテキストとチェックアイコンが表示され、申し込みボタンがHTML上に存在しないこと。

---

### シナリオ 2: 非公開イベントへのアクセス制御 (TS_SHO_06, TS_SHO_07)

#### 前提条件
*   一般ユーザーA（ログイン状態）、および管理者ユーザーB（ログイン状態）が存在すること。
*   **イベント4**: ステータス「下書き (draft)」、タイトル「マル秘セミナー」が登録されていること。

#### 操作手順
1.  一般ユーザーAとして `/events/[イベント4のID]` へGETリクエストを送信する。
2.  管理者ユーザーBとして `/events/[イベント4のID]` へGETリクエストを送信する。

#### 期待される結果
1.  一般ユーザーAのアクセス：ステータスコード `404 Not Found` が返却されること。
2.  管理者ユーザーBのアクセス：ステータスコード `200 OK` が返却され、タイトル「マル秘セミナー」のイベント詳細画面が正しく表示されること。
