# 複数イベント一括予約処理 テスト仕様書

複数イベント一括予約処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_BLK_01** | 正常系 | 複数イベントを選択し、すべて予約可能な状態で実行する | ・すべての予約レコードがDBに作成されること<br>・「○件の申し込みが完了しました ([タイトル1], [タイトル2])」と成功Flashが表示されること |
| **TS_BLK_02** | 正常系 | 複数のイベントを同時に申し込み、一部のみ成功し一部が失敗する | ・成功したイベントの予約のみがDBに登録され、失敗したイベントは登録されないこと（部分成否）<br>・成功した件数のグリーンメッセージ、および失敗したイベントと具体的な理由のレッドアラートメッセージが同時に表示されること |
| **TS_BLK_03** | 正常系 | 選択チェックボックスが空の状態で一括予約を実行する | ・データ登録処理が走らないこと<br>・「イベントが選択されていません」とアラートが表示されリダイレクトされること |
| **TS_BLK_04** | 異常系 | 未ログイン状態で一括予約API（POST）を送信する | ・データが登録されないこと<br>・ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 部分成功・一部失敗シナリオ (TS_BLK_02)

#### 前提条件
*   一般ユーザーAが存在し、ログイン状態であること。
*   以下のイベントデータが登録されていること：
    *   **イベント1**: タイトル「Rails勉強会」、定員5、予約数2（空きあり）
    *   **イベント2**: タイトル「Railsもくもく会」、定員2、予約数2（満席）
*   ユーザーAはいずれのイベントも未予約であること。

#### 操作手順
1.  クライアントから `POST /events/1/bookings/bulk_create` に対して、パラメータ `event_ids: [1, 2]` を含めて送信する。

#### 期待される結果
1.  ステータスコード `302 Found` で `events_path` へリダイレクトされること。
2.  リダイレクト後の画面（Flash notice）に「1件の申し込みが完了しました (Rails勉強会)」という通知が含まれていること。
3.  リダイレクト後の画面（Flash alert）に「【Railsもくもく会】定員に達しているため申し込みできません」という文言が含まれていること。
4.  データベースの `bookings` テーブルに、ユーザーAと **イベント1** を紐づける予約レコードのみが1件追加されていること（イベント2の予約レコードはないこと）。

---

### シナリオ 2: 空パラメータ送信のガード (TS_BLK_03)

#### 前提条件
*   一般ユーザーAが存在し、ログイン状態であること。

#### 操作手順
1.  `POST /events/1/bookings/bulk_create` に対して、`event_ids` パラメータを含めずに（または空配列を指定して）送信する。

#### 期待される結果
1.  ステータスコード `302 Found` でリダイレクトされること。
2.  アラートメッセージに「イベントが選択されていません」と表示されていること。
3.  データベースの予約レコードが一切追加されていないこと。
