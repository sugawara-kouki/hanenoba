# イベント一覧表示処理 テスト仕様書

イベント一覧表示および検索処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_IDX_01** | 正常系 | ログイン状態でイベント一覧へアクセスする | ・ステータス 200 OK となり、公開中のイベントが開催日時昇順で表示されること<br>・下書き状態（draft）のイベントが表示されないこと |
| **TS_IDX_02** | 正常系 | キーワード検索を実行する（params[:q]） | ・指定キーワードがタイトルに含まれるイベントのみが表示されること |
| **TS_IDX_03** | 正常系 | 開催日検索を実行する（params[:date]） | ・指定した日付の期間中に開催されるイベントのみが表示されること |
| **TS_IDX_04** | 正常系 | 空き枠数検索を実行する（params[:capacity]） | ・（定員 － 予約数）が指定値以上のイベントのみが表示されること |
| **TS_IDX_05** | 正常系 | 状態バッジ（申込済・満席）の描画 | ・自身が予約済みのイベントに「申込済」バッジが表示されること<br>・定員に達したイベントに「満席」バッジが表示されること<br>・これら2つのイベントの一括予約用チェックボックスが非活性（disabled）であること |
| **TS_IDX_06** | 正常系 | ページネーション（Pagy）の動作 | ・イベント数が12件を超える場合、1ページ目には12件のみが表示されること<br>・ページ遷移リンクが表示され、2ページ目に残りのイベントが表示されること |
| **TS_IDX_07** | 異常系 | 未ログイン状態でイベント一覧へ直接アクセスする | ・アクセスが拒否され、ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 複合条件でのイベント絞り込みとバッジ検証 (TS_IDX_02, TS_IDX_04, TS_IDX_05)

#### 前提条件
*   一般ユーザーAが存在し、ログイン状態であること。
*   以下のイベントデータが登録されていること：
    *   **イベント1**: タイトル「Rails勉強会」、定員5、予約数2、開催日「2026/06/01」（空き枠: 3）※ユーザーAは未予約
    *   **イベント2**: タイトル「Railsもくもく会」、定員2、予約数2、開催日「2026/06/02」（空き枠: 0）※ユーザーAは未予約（満席）
    *   **イベント3**: タイトル「JavaScript勉強会」、定員3、予約数1、開催日「2026/06/03」（空き枠: 2）※ユーザーAが予約済み（申込済）
    *   **イベント4**: タイトル「Railsセミナー」(下書き)、定員10、予約数0、開催日「2026/06/04」

#### 操作手順
1.  ブラウザまたはクライアントから `/events?q=Rails&capacity=2` をリクエストする。

#### 期待される結果
1.  ステータスコード `200 OK` が返却されること。
2.  表示されるイベントが **イベント1** のみであること。
    *   イベント2は満席（空き枠0 < 2）のため除外。
    *   イベント3はキーワードが不一致（JavaScript）のため除外。
    *   イベント4は「下書き」のため除外。
3.  表示されたイベント1のカードについて、チェックボックスが活性状態（`disabled`属性がない）であり、申込済や満席のバッジがないこと。

---

### シナリオ 2: 未ログイン時のリダイレクト (TS_IDX_07)

#### 前提条件
*   クライアントは未ログイン状態であること。

#### 操作手順
1.  `/events` へ直接GETリクエストを送信する。

#### 期待される結果
1.  ステータスコード `302 Found` が返却されること。
2.  リダイレクト先がログイン画面（`/login`）であること。
