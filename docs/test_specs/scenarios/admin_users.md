# 会員管理 テスト仕様書

管理者用会員管理（承認トグル、詳細履歴、なりすましログイン、削除）処理の品質を保証するために検証すべきテスト観点およびテストシナリオを定義します。

---

## 1. テスト観点一覧

| 観点ID | カテゴリ | テスト観点 | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **TS_USR_01** | 正常系 | 会員一覧の表示とソートを実行する | ・会員一覧が表示され、指定カラムでソートされること |
| **TS_USR_02** | 正常系 | 会員詳細画面で予約申込履歴を確認する | ・対象会員が過去に申し込んだすべてのイベント履歴が時系列で正しく表示されること |
| **TS_USR_03** | 正常系 | 承認ステータスをトグル更新する（未承認 → 承認） | ・`approved` フラグが `true` に切り替わること<br>・一覧画面へリダイレクトされ、更新通知が表示されること |
| **TS_USR_04** | 正常系 | 承認ステータスをトグル更新する（承認 → 未承認） | ・`approved` フラグが `false` に切り替わること<br>・一覧画面へリダイレクトされ、更新通知が表示されること |
| **TS_USR_05** | 正常系 | 会員レコードを削除する（カスケード削除） | ・`users` レコードが物理削除されること<br>・そのユーザーが予約していた `bookings` レコードも自動的に物理削除されること |
| **TS_USR_06** | 正常系 | 【開発環境】なりすましログインを実行する | ・指定した一般会員のセッションが開始され、一般トップページへリダイレクトされること |
| **TS_USR_07** | 異常系 | 【本番/テスト環境】なりすましログインを要求する | ・ルーティングエラー（404）となるか、要求が無視されること（なりすましセッションが開始されないこと） |
| **TS_USR_08** | 異常系 | 一般ユーザーのセッションで会員管理APIにアクセスする | ・アクセスがブロックされ、管理者ログイン画面へリダイレクトされること |

---

## 2. 具体的なテストシナリオ

### シナリオ 1: 承認トグル切り替えの検証 (TS_USR_03, TS_USR_04)

#### 前提条件
*   管理者ユーザーがログイン状態であること。
*   一般ユーザーA（未承認: `approved: false`）がDBに登録済みであること。

#### 操作手順
1.  会員一覧画面（`/admin/users`）へアクセスする。
2.  一般ユーザーAの「承認待ち」トグルスイッチを押下する（`PATCH /admin/users/[ユーザーAのID]` 送信）。
3.  更新後のフラッシュメッセージおよびDB値を確認する。
4.  再度ユーザーAのトグルスイッチを押下する。
5.  更新後のDB値を確認する。

#### 期待される結果
1.  手順2の後、ステータス `302 Found` で `/admin/users` へリダイレクトされること。
2.  手順3において、画面上部に「[ユーザーAの名前]のステータスを更新しました」と緑色のFlashが表示されること。
3.  手順3において、DB上のユーザーAの `approved` フラグが `true` に更新されていること。
4.  手順4の後、DB上のユーザーAの `approved` フラグが `false` に更新されていること。

---

### シナリオ 2: なりすましログインの環境ガード検証 (TS_USR_06, TS_USR_07)

#### 前提条件
*   管理者ユーザーがログイン状態であること。
*   検証用一般ユーザーAがDBに登録済みであること。

#### 操作手順（開発環境）
1.  `Rails.env.development?` が `true` の環境（開発環境）で、管理者として `/admin/users` へアクセスする。
2.  ユーザーAの行にある「なりすましログイン」ボタンを押下する。

#### 操作手順（本番環境）
1.  `Rails.env.production?` が `true` の環境（本番環境）で、管理者としてログインし、直接 `POST /admin/users/[ユーザーAのID]/impersonate` を送信する。

#### 期待される結果
1.  **開発環境**: 
    *   ボタン押下後、一般トップページ（`/`）へリダイレクトされること。
    *   画面に「[ユーザーAの名前]としてログインしました」と通知が表示され、セッションがユーザーAに切り替わっていること。
2.  **本番環境**:
    *   API送信後、ルーティング定義がないため `ActionController::RoutingError` (404) が返却されるか、アクセスが遮断されること。
    *   一般ユーザーAへのなりすましセッションは絶対に開始されないこと。
